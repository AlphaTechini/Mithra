## Decision from the product owner (this replaces the earlier M10 design)
There is **no MainNet node**. So on MainNet Mithra cannot host its Daml package or read the MainNet ledger. Therefore:
- **Mithra's records always live on the LocalNet ledger** (organization, Mandate, proposals, approvals, decision records, payments, audit grants), signed server-side exactly as today, with the role switcher and BitSafe governance.
- **`NETWORK=mainnet` means "MainNet payouts"**: the money moves on Canton MainNet as real CC transfers from the treasurer's Grofty Wallet, using Grofty's plain transfer `prepareExecuteAndWait({ receiver, amount, memo })`, which needs no Mithra package and no node. The Mandate's ledger rules (cap, pro-rata, one per cycle, approval threshold) still decide on the LocalNet ledger **before** any MainNet transfer is offered for signing.
- Holders connect Grofty to register the MainNet party they are paid to, and are guided to turn on auto-receive in Grofty (N5).
- Every MainNet payment links to the MainNet explorer (P3); "Paid" appears only after Grofty reports the transfer executed (P4).
- Record this as decision 11 in `docs/decisions.md` (and note the spec deviation for N6: user actions other than payouts are signed on LocalNet, not by each user's Grofty party, because there is no MainNet node to host Mithra's contracts).

## Design you must follow
**Daml** (`daml/mithra`, tests in `daml/mithra-tests`; the package is not deployed anywhere yet, so change v0.1.0 in place; update `docs/ledger-model.md`):
- `PaymentStatus` gains `PendingExternal`. `Payment` gains `externalReceiver : Optional Party` is not possible (MainNet parties are not LocalNet parties): use `externalReceiver : Optional Text` and `externalTxRef : Optional Text`.
- `Mandate_AuthorizeExternalPayout` (consuming like `Mandate_AgentExecute`, `controller agent`) with `proposalCid` and `receivers : [(Party, Text)]` (each payee's MainNet party id, in payout order): runs **the same checks** as `executeDistribution` (treasury/agent match, cycle not executed, cap for `AutoExecute` against current terms, distinct current approvers ≥ threshold for `NeedsApproval`, receivers line up with payouts and are non-empty strings), adds the cycle to `executedCycles`, and through `Proposal_MarkExecuted` creates one `Payment` per payee with status `PendingExternal` and `externalReceiver`, and the `Executed` outcome. No token-standard transfer happens on LocalNet in this path. Factor the shared checks so both paths use one function.
- `Payment_RecordExternal` (`controller agent`) with `txRef : Text` and `status : PaymentStatus` (`Paid` or `AwaitingAcceptance`): only from `PendingExternal` or `AwaitingAcceptance`; recreates the Payment with the tx ref and status. (The ledger cannot verify a MainNet transfer; this is the agent's attestation of what Grofty reported. Say so in a comment and in `docs/ledger-model.md`.)
- Tests: external path L1 (cap + epsilon blocked), L3 (second authorize fails), L4 (1 of 2 fails, 2 of 2 succeeds), receivers mismatch fails, only the agent can authorize and record, a holder sees only their own Payment (L7), recording from `Paid` fails. `scripts/daml.sh test` passes (all existing tests too).
