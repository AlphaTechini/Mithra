## Verified API notes
JSON Ledger API v2 (Canton 3.5.8 spec; create/ACS/party calls verified live against a 3.4 sandbox, see `docs/research/ledger-api.md`):
- `POST /v2/commands/submit-and-wait-for-transaction` body `{ "commands": { "commandId", "userId", "actAs": [..], "readAs": [..], "commands": [ { "CreateCommand": { "templateId", "createArguments" } } | { "ExerciseCommand": { "templateId", "contractId", "choice", "choiceArgument" } } ], "disclosedContracts": [ { "templateId", "contractId", "createdEventBlob", "synchronizerId" } ] }, "transactionFormat"?: { "transactionShape": "TRANSACTION_SHAPE_ACS_DELTA" | "TRANSACTION_SHAPE_LEDGER_EFFECTS", "eventFormat": {...} } }` → `{ "transaction": { "updateId", "commandId", "effectiveAt", "offset", "synchronizerId", "recordTime", "events": [ { "CreatedEvent": {...} } | { "ArchivedEvent": {...} } | { "ExercisedEvent": {...} } ] } }`. Use LEDGER_EFFECTS shape when you need a choice's `exerciseResult` (ExercisedEvent has `exerciseResult`); otherwise read created contracts from CreatedEvents.
- `POST /v2/state/active-contracts` `{ "activeAtOffset": <GET /v2/state/ledger-end .offset>, "eventFormat": { "filtersByParty": { "<party>": { "cumulative": [ { "identifierFilter": { "TemplateFilter": { "value": { "templateId": "#mithra-v1:Mithra.Org:Organization", "includeCreatedEventBlob": false } } } } ] } }, "verbose": false } }` → JSON array of `{ "contractEntry": { "JsActiveContract": { "createdEvent": { "contractId", "templateId", "createArgument", "signatories", "observers", "createdAt", "offset", "createdEventBlob"? }, "synchronizerId" } } }`. Interface filter: `{ "InterfaceFilter": { "value": { "interfaceId": "#splice-api-token-holding-v1:Splice.Api.Token.HoldingV1:Holding", "includeInterfaceView": true, "includeCreatedEventBlob": true } } }`; the view arrives in `createdEvent.interfaceViews[].viewValue`.
- Parties: `POST /v2/parties { "partyIdHint", "identityProviderId": "" }` → `{ "partyDetails": { "party" } }`; `GET /v2/parties`. Rights: `POST /v2/users/{user-id}/rights { "userId", "rights": [ { "kind": { "CanActAs": { "value": { "party": p } } } }, { "kind": { "CanReadAs": { "value": { "party": p } } } } ] }`. Upload DAR: `POST /v2/dars` raw bytes, `Content-Type: application/octet-stream`. Version: `GET /v2/version`. Synchronizers: `GET /v2/state/connected-synchronizers`.
- Template ids in requests: package-name form `#mithra-v1:<Module>:<Entity>`; responses contain `<packageId>:<Module>:<Entity>`. Compare by `Module:Entity` suffix.
- Daml-LF JSON: `Decimal`, `Int` as strings (send strings; parse back with `DecimalString` and integer parsing); `Party`, `ContractId`, `Text` strings; `Time` ISO-8601; `Date` `"YYYY-MM-DD"`; `Optional` null or value; lists arrays; records objects; enums as strings (`"AutoExecute"`, `"TriggerSchedule"`, `"Paid"`); variants `{ "tag": "RefDecision", "value": "<cid>" }`; tuples `{ "_1": a, "_2": b }`; `TextMap` as a JSON object. **Verify every non-trivial shape (variant, tuple, TextMap, nested Optional) in your sandbox integration tests**; adjust the codec, not the tests, if the ledger disagrees.
- Errors: `{ "code": "DAML_FAILURE", "cause": "Interpretation error: Error: User failure: UNHANDLED_EXCEPTION/…: <message>", "context": {...}, "errorCategory": 9, ... }`. Daml `assertMsg` text is inside `cause`. Map to a `LedgerError { code, message (the Daml message, cleaned), retryable }`.
- Auth: LocalNet = HS256 JWT signed with `LEDGER_HMAC_SECRET` (default LocalNet value `unsafe`), claims `{ "aud": LEDGER_AUDIENCE ("https://canton.network.global"), "sub": LEDGER_USER_ID ("ledger-api-user") }` (use `jose`); MainNet = OIDC client credentials (`POST LEDGER_OIDC_TOKEN_URL` form `grant_type=client_credentials&client_id&client_secret&audience&scope`, cache until shortly before `expires_in`); `none` mode for the sandbox (no Authorization header).
