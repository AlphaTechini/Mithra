## Goal
The treasurer (and approvers, read-only) can talk to the agent. The agent drafts policy from plain English, creates cycle proposals from a prompt ("Distribute 1,200 CC for September") and from the schedule, explains proposals, answers questions about history with numbers computed in code, drafts audit scopes, and shows every tool call as an action card. It can never move money outside the Mandate, sign a Mandate, approve a proposal, grant audit access, compute payout amounts or clear a deterministic flag. If the model is down or answers nonsense, nothing executes, the reason is shown, and deterministic checks still appear. Every model request and response is fingerprinted. A scheduler runs cycles on the Mandate's schedule without ever double-running; expired access grants close within 5 minutes; a Server-Sent Events stream feeds the live timeline and status updates.

## Design you must follow
- `llm/client.ts` — **the only module that talks to the model** (T5). `createLlm(config)` → `Llm { chat({ messages, tools?, toolChoice?, purpose }): Promise<LlmTurn> }` using `new OpenAI({ baseURL, apiKey, timeout, maxRetries: 1 })` and `client.chat.completions.create({ model, messages, tools, tool_choice, parallel_tool_calls: false })`. `LlmTurn` = `{ message, toolCalls: { id, name, arguments: string }[], requestFingerprint, responseFingerprint }` where fingerprints are SHA-256 of canonical JSON of the request body (model, messages, tools) and of the response message. Any thrown error → `LlmUnavailableError(reason)` with a short reason ("timed out after 30 s", "401 from the model provider", "model provider unreachable"). Config additions: `LLM_STRICT_TOOLS` (default `false`; send `strict: true` on function tools when true), `LLM_MAX_TOOL_ROUNDS` (default 4).
- `agent/tools/*.ts` — one file per tool: `name`, `description` (written for the model, including what the tool will **not** do), Zod `parameters` (converted with `z.toJSONSchema`), `roles` allowed (`treasurer` for writes; `approver` may use `explain_proposal`, `query_history`, `get_balance`, `list_holders`), and `run(args, ctx)` → `{ card: ActionCardView; result: unknown }` (the `result` goes back to the model as the tool message; the card goes to the UI). Validate `JSON.parse(arguments)` with the Zod schema; on failure the tool is **not** run and the card is `failed` with "The agent's request was malformed, so nothing was done."
  - `draft_policy` / `propose_mandate_change` — parameters are the `PolicyFields` minus approver party ids, plus approver **names** (`approverNames: string[]`) resolved by code against `org.parties()` (unknown names → card `failed` asking the treasurer to pick approvers on the form). Saves a draft (`source: 'agent'`); card status `needs-you`, title "Drafted a policy for you to review and seal" / "Drafted a Mandate change. Review and re-seal to apply it.", link `/setup/policy` or `/app/settings`. Never seals.
  - `create_cycle` — parameters `{ total: DecimalString, period?: 'YYYY-MM', recordDate?: 'YYYY-MM-DD' }`: the **requested** total the user stated (A2). Per-holder amounts are never parameters (the schema has no such field; a test proves extra fields are rejected or ignored). Calls `cycles.run({ trigger: 'prompt', promptText: <the user's message>, modelFingerprints: <this turn's request/response fingerprints>, … })`, waits up to 15 s for the proposal (poll `getCycle`), card "Created proposal for September, 4 payees, 1,200 CC" with link `/app/cycles/<id>`.
  - `run_cycle_now` — `cycles.run({ trigger: 'manual' })` with defaults.
  - `explain_proposal` — returns the cycle detail (checks with actual values, memo, verdict reasons) for the model to explain; card "Explained September 2026".
  - `query_history` — parameters `{ holderName?, from?, to? }` (names resolved in code); the tool returns rows **and the sums computed in code with decimal.js**; the model is instructed to quote the sums as given.
  - `list_holders`, `get_balance`, `issue_units` (`{ holderName, units }`), `invite_holder` (`{ displayName }`), `close_expired_grants` (calls the expiry job now).
  - `draft_audit_scope` — used by the audit flow (M9), see below; available to the agent chat for the treasurer as well.
  - No tool may sign a Mandate, approve or reject a proposal, grant or deny audit access, or execute payments. Add a unit test that lists the registered tool names and fails if any name or description suggests approve/sign/grant/execute capabilities beyond the list above.
- `agent/agent.ts` — `createAgent({ llm, services, names, bus, db, activity })` → `respond({ partyId, roles, text })`: loads the last 20 messages for the party from `chat_messages`, builds the system prompt (who the agent is, the Mandate's cap and threshold from `services.org.mandate()`, the rules it must follow, the vocabulary), runs the tool loop up to `LLM_MAX_TOOL_ROUNDS`, stores messages, publishes an `agent` event per card, and returns `SendAgentMessageResponse`. Guardrails in code, not only in the prompt:
  - Only tools allowed for the caller's roles are offered and runnable.
  - **A6 sentence in code**: if a `create_cycle` result's verdict is needs-approval because the total is above the cap, the reply text ends with the code-generated sentence `<total> CC is above your auto-pay cap of <cap> CC. I've prepared this as a proposal that needs <k> of <n> approvals.` (whatever the model wrote).
  - **A11**: any `LlmUnavailableError` → reply `degraded: true`, text `I can't reach the language model right now (<reason>). Nothing was executed. You can still use Run cycle now and the screens.`; no tool runs. Invalid tool arguments → that tool does not run (see above).
  - Model text that contains amounts is never parsed into any amount used by the system.
- `agent/memoWriter.ts` — `AiMemoWriter` implementing `MemoWriter`: one LLM call with a forced tool `write_review { memo: string; advisoryFlags: { label: string; detail: string }[] }`, turned into `advisoryChecks` with `code: 'ai_advisory'`, `source: 'ai'`, **`blocking: false`**, `passed: false`. On `LlmUnavailableError` or invalid output: deterministic template memo from the checks, `memoSource: 'ai-unavailable'`, and the memo starts with `AI review unavailable: <reason>. Deterministic checks below are complete.` `modelFingerprints`: `memo.request`, `memo.response`.
- `agent/policyDrafter.ts` — `draftPolicy(prompt, party)` for `POST /api/policy/draft`: one LLM call with a forced `draft_policy` tool, Zod-validated, approver names resolved, `services.policy.saveDraft`. Fallback on LLM failure: `503 llm_unavailable` "The agent can't draft right now (<reason>). Fill in the policy form yourself; nothing was changed." The demo prompt `Pay monthly yield on the 1st. Auto-pay if the total is under 5,000 CC and nothing looks off. Otherwise 2 of 3 approvals.` must map to: cron `0 9 1 * *`, timezone UTC, `last_day_of_previous_month`, cap `5000`, threshold 2 with 3 approvers, deviation 50%, trailing 3 cycles, unit change 100% over 3 days (the defaults in userflow section 4 step 2 when the prompt does not say), fee buffer `1`.
- `audit/scope.ts` — `draftAuditScope(question, catalog)` where `catalog: { recordId: string; kind: 'decision' | 'outcome'; cycleId: string; cycleLabel: string; flagged: boolean; executedAt: string | null }[]` (built by the caller from the ledger): one LLM call with a forced tool `propose_scope { items: { recordId, reason }[], excluded: string }`; code keeps only record ids that exist in the catalog, de-duplicates, and returns `{ items: ScopeItem[], excluded, source: 'ai' | 'rules' }`. Instruct the model to prefer the smallest set. Fallback without the model (A11): a deterministic rule-based scope (parse quarters "Q3", month names and years; "flagged" keeps flagged cycles' decision and outcome records; otherwise all records in the period), `source: 'rules'`, with `excluded` "Holder identities are shown as Holder A to D unless you ask for them".

- `scheduler/index.ts` — `startScheduler({ services, ledger, db, bus })`: reads the Mandate's `scheduleCron`/`scheduleTimezone`, schedules a `croner` job; on fire computes the cycle id (previous month), and calls `services.cycles.run({ trigger: 'schedule', … })`; the engine's `cycle_runs` unique key is the double-run guard, and the scheduler also checks `cycle_runs` before calling. Re-reads the Mandate every 5 minutes and reschedules when the cron changes. If the policy has no fixed amount, it does not guess: it records an agent event and activity entry "Schedule fired for September 2026; no amount set. Tell the agent how much to distribute." Expose `fireNow()` for tests and `stop()`.
- `routes/agent/index.ts` — `agentRoutes(app, { agent, drafter, scope })`: `GET /api/agent/messages` (treasurer, approver; own conversation + suggestions from userflow section 8), `POST /api/agent/messages` (Zod-validated; rate limit 20/min per party), `POST /api/policy/draft` (treasurer), `POST /api/audit/scope/draft { question }` (auditor or treasurer; returns the scope; the catalog comes from a `catalog()` dependency you define).
